# ADR 0005：设计语言采用「墨韵」——水墨画式的界面与动效

- **状态**：已接受
- **日期**：2026-10
- **相关**：[设计规范](../design/设计规范.md)、[ADR 0002](0002-shell-rust-smithay.md)（合成器）、[ADR 0003](0003-web-内核-wpe-webkit.md)（Web 内核）

## 背景

第一版界面的反馈是**“UI 太丑”**。逐项看，问题集中在视觉，而不在交互：

- 渐变底板加细线条图标，像通用的网页模板，没有辨识度；
- 壁纸发闷，毛玻璃太弱，状态栏与排版缺乏质感；
- 演示应用只是纯色块。

同时，动画（`loong-motion` 的弹簧、惯性、橡皮筋，可打断并继承速度）是现有最好的部分，必须保留。约束如下：

1. **只重做视觉**：交互模型与物理参数不变，动效换一种“表现”，不换引擎。
2. **体积小**：镜像目标 ≤ 250MB，不能为了好看带上大量位图资源。
3. **省电**：静止时不重绘；特效只在交互期间计算（见设计规范“克制省电”）。
4. **两套外观**：亮色与暗色都要做，默认亮色。
5. **两条渲染路径一致**：系统界面由 Rust 合成器绘制（`loong-ui` + GLES 着色器），系统应用与 PWA 由 WPE WebKit 渲染（LoongKit）。同一种语言要能在两边都实现，并且在 WebKit 中只依赖合成线程友好的特性。

用户给出的方向是：**Loong 东方风格，参考水墨画，重新做一套设计语言——使用起来如同水墨画动起来、如同在绘画一般**；壁纸程序生成；展示字体用楷体；图标外形用“宣纸小笺”。

## 决策

采用「墨韵」设计语言，完整规范见[设计规范](../design/设计规范.md)。要点：

- **五条原则**：留白、墨分五色、笔意、气韵生动、虚实。
- **令牌**（`crates/loong-ui/src/theme.rs` 为唯一来源）：
  - 外观：亮色「宣纸」（纸 `#F3EEE2`、熟宣 `#EAE3D3`）与暗色「夜墨」（`#15140F`、墨绢 `#1F1D17`），默认亮色；
  - 墨五色：焦 / 浓 / 重 / 淡 / 清，暗色反转为“月白”系；
  - 传统颜料：朱砂（品牌与重要提示）、胭脂、藤黄、赭石、石青、石绿、花青，暗色另加泥金（暗色中代替墨做开关、滑块、选中项）。
- **字体**：展示字体用霞鹜文楷屏幕版（LXGW WenKai Screen，SIL OFL 1.1），只用一个字重；正文仍为 Inter + Noto Sans CJK SC。
- **材质**：宣纸（不透明，纤维纹理）、素笺（卡片）、绢（半透明：模糊 + 暖色 + 细丝）、烟（雾带）、墨影（暖色柔和阴影）。
- **视觉元素**：程序生成的「山水长卷」分层壁纸；「宣纸小笺」图标（宣纸底板 + 没骨色晕 + 由 Lucide 自动转换的毛笔笔触）；毛笔画的状态栏符号；文楷时间与农历日期；朱砂印章。
- **动效**：沿用 `loong-motion` 的全部弹簧预设，把它们映射成水墨表现——点墨（按下）、晕染开启 / 收墨（开关应用）、笔迹（系统手势）、展卷（翻页视差）、墨散（解锁）、落印（确认）。只在交互期间计算，“减弱动态效果”时退化为淡入淡出。
- **实现分工**：
  - `loong-ui::ink`：CPU 上一次性画出纸纹、笔触、山水分层、图标、印章、墨影，按（主题、尺寸、版本）缓存；
  - `loong-shell`：`ink_fx.frag`（墨点、笔迹印）与 `shader.frag` 的晕染遮罩；壁纸分层视差；
  - LoongKit：CSS 令牌 + 程序生成的内联 SVG 纹理（`tools/loongkit-textures.py`）+ 约 3 KB 的 `loongkit.js`（点墨、落印、外观切换），只动 `transform` / `opacity`。

## 备选方案及不选原因

| 方案 | 不选原因 |
|---|---|
| **iPadOS 式玻璃**（大面积毛玻璃、高饱和渐变、白色线条图标，即在原方案上加强） | 问题恰恰是“像别人”：再精致也只是另一个 iPadOS 仿制品，没有辨识度，且容易在外观上过于接近 Apple。大面积实时模糊在应用之上每帧都要算，对小米平板 5 的 GPU 与功耗都不友好；毛玻璃在浅色壁纸上层次弱，正是第一版被嫌“太弱”的地方 |
| **极简单色**（黑白灰、纯线条、无纹理） | 实现最便宜，但冷而空，和“太丑”里“缺乏质感”的批评同向；只靠灰阶难以表达状态与层级，最后仍会加回一个品牌色，回到“模板感”。也无法回应“像在绘画”的诉求 |
| **保留 Loong 青配色，只改排版与图标** | 改动小，但青色渐变本身就是“网页模板感”的来源之一；不换语言就无法让动效有新的表现 |
| **位图素材的水墨风**（手绘壁纸、图标 PNG） | 质感可以更好，但体积大、分辨率与外观（亮 / 暗）组合多、每加一个应用都要手绘；程序生成可以在两种外观、任意分辨率下保持一致，并支持视差分层 |

## 影响 / 后果

**正面**

- 有了自己的辨识度：纸、墨、印章、文楷、山水，一眼可辨，又与中文用户的审美习惯一致。
- 动效引擎不变，只换表现：所有动画仍可打断、继承速度，测试与参数全部沿用。
- 视觉资源几乎全部程序生成：亮 / 暗两套外观、任意分辨率，不增加镜像中的位图。
- 层级主要靠墨色浓淡而不是颜色：正文对纸的对比度 12.7:1（亮）/ 11.1:1（暗），两种外观都满足 WCAG AA。

**负面与需要承担的工作**

- **字体体积约 +10MB**：霞鹜文楷屏幕版按 GB18030 常用字 + 拉丁裁剪（`system/packages/font-lxgw-wenkai`），附 OFL 许可证；缺失时回退到思源黑体，界面仍可用，但失去展示字体。
- **程序生成资源的开机成本**：壁纸分层 + 全部图标在小米平板 5 上目标 ≤ 1.5s，之后读缓存（`/var/cache/loong/assets/`）；需要缓存失效策略（主题、尺寸、生成器版本）。
- **新增着色器特效**：墨点、笔迹、晕染遮罩会增加 GPU 负担；约束为只在交互期间计算、墨点只画小矩形、fbm ≤ 3 个八度，并以 120fps 为目标做性能回归（headless 打印每帧渲染耗时）。
- **Web 端**：纹理是 SVG 滤镜，首次栅格化有 CPU 成本（每种纹理一次）；不得在大面积内容上用 `filter: url()`。Chromium 截图与 WPE 渲染略有差异，最终以设备为准。
- **品牌色变化**：品牌色从“Loong 青”改为朱砂，且朱砂用量受限（只用于印章、角标、警示）。旧的 Loong 青令牌需要清理，相关文档与图标同步更新。
- **对比度的边界**：淡墨（3.4–4.0:1）不能用于正文；朱砂文字在熟宣上只有 4.47:1，只能放在宣纸与素笺上——这些规则写入设计规范与可访问性清单。
- **风格风险**：水墨元素若堆得太多会显得“做作”。以留白为第一原则，装饰（山水、题款、印章）集中在少数几处（卷首、锁屏、关于本机），功能界面保持克制。
