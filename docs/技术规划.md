# Loong OS 技术规划

> 状态：已批准（v1 规划）。架构上的关键取舍见 [ADR](adr/README.md)，界面与动效规范见[设计规范](design/设计规范.md)。

## 背景与目标

Loong OS 是一款基于 Linux 的平板操作系统，目标如下：

- **尽可能小、资源占用低**；不基于 Android。
- **全新 UI**：参考 Apple HIG 的设计原则，所有系统动画都基于物理模型（弹簧、惯性、橡皮筋）。
- **应用即 PWA**：不建设原生应用生态。浏览器基于 WebKit 开源内核。
- **第一版面向 ARM64 平板。**

已确认的范围与约束：

| 项 | 结论 |
|---|---|
| 硬件 | ARM64 平板，参考设备是小米平板 5（nabu） |
| Shell | 用 Rust 自研 Wayland 合成器（基于 Smithay） |
| v1 功能 | 拼音输入法、音视频、OTA A/B 更新，以及 Wi‑Fi、亮度、电池设置 |
| 许可证 | MIT OR Apache-2.0。GPL 代码（如 niri）只参考思路，不复制；合成器以 Smithay 自带的 MIT 许可参考合成器 anvil 为起点 |

## 一、技术选型

| 层 | 选择 | 理由 / 已验证事实 |
|---|---|---|
| 基础发行版 | **Alpine Linux 3.24**（musl + busybox） | 基础系统约 8MB。mesa 26.1、libinput、seatd、iwd、pipewire、gstreamer 1.28、librime 1.17、erofs-utils、systemd-boot/efistub、ukify、font-inter、qemu、ovmf 均已确认有预编译包 |
| 设备适配 | 复用 **postmarketOS v26.06** 的内核与固件包（对应 Alpine 3.24；镜像已迁至 `mirror.nura.eco/postmarketos/`） | **不安装** `device-xiaomi-nabu` / `postmarketos-base`：它们会拖入 pmOS initramfs、btrfs/xfs/cryptsetup、sshd、sudo 等。改为自建 `loong-device-xiaomi-nabu`，只依赖内核、固件、qbootctl、tqftpserv、pd-mapper |
| 参考设备 | **小米平板 5（nabu）**：骁龙 860、Adreno 640、6GB 内存、2560×1600 120Hz 屏幕 | pmOS v26.06 已有 nabu 端口（内核 `linux-postmarketos-qcom-sm8150` 6.17，高通厂商 fork，非 LTS）；GPU 用 Mesa freedreno 主线驱动；国内容易买到 |
| 开发/CI 目标 | 以 QEMU x86_64（q35）为主，用 aarch64（virt）验证架构；virtio-gpu + virtio-multitouch | 代码与架构无关；沙箱没有 KVM，x86_64 在 TCG 下最快 |
| init / 设备 | **OpenRC** + eudev + **seatd** + D-Bus | 不用 systemd/logind |
| 网络 | **iwd**（内置 DHCP） | 不用 NetworkManager |
| 音频/媒体 | GStreamer：Alpine 的核心与 gst-plugins-base，加自编的最小插件集 `gst-plugins-loong`（nabu 用 V4L2 Venus 硬解），H.264、AAC 软解用只含这两个解码器的 FFmpeg（`ffmpeg-loong` + `gst-libav-loong`）；nabu 的扬声器开机时设 UCM 用例、ALSA 默认设备经 dmix（不用声音服务），以后换 PipeWire + WirePlumber | WebKit 的媒体功能依赖 GStreamer；支持的格式见[媒体格式](媒体格式.md) |
| Web 内核 | **WPE WebKit 2.54.2**（自行打包 APK，参考 Chimera Linux 的 musl 配置） | Alpine 不提供 WPE。从 2.54 起，WPEPlatform API 已稳定并成为默认，带 Wayland 后端和 text-input-v3 输入法支持 |
| Shell | **Rust + Smithay（固定 git 版本）**，自研合成器 `loong-shell` | Smithay 0.7.0 已发布 16 个月，主干仍很活跃；`default-features = false` |
| 2D 绘制 | 用 tiny-skia + cosmic-text + resvg 栅格化到纹理，再由 GLES2 合成 | 沿用 Core Animation 的思路：图层只栅格化一次，变换、透明度、模糊动画都由合成器完成 |
| 根文件系统 | **只读 erofs（lz4hc）** + A/B 双分区 + 可写的 `/data` | `/var`、`/etc/machine-id`、`resolv.conf`、`hostname`、`/var/lib/iwd` 由 initramfs 从 `/data` bind 挂载，或用 tmpfs 提供 |
| 启动 | 自写 busybox initramfs + 两种启动后端（见下） | Alpine 的 `mkinitfs` 不支持 erofs/dm-verity；`linux-virt` 内核中的 erofs、virtio-blk、dm-verity 都是模块 |
| 输入法 | 合成器内置屏幕键盘 + **librime** 拼音；协议上 `input-method-v2` ↔ `text-input-v3` | WPE 已有 `WPEInputMethodContextWaylandV3` |
| 字体/图标 | Inter + Noto Sans CJK SC（子集：GB2312 + 通用规范汉字表，可变字重，4 MiB）+ 霞鹜文楷（展示）；自绘图标 + Lucide（ISC）符号 | 不使用 SF Pro、苹方、SF Symbols（受 Apple 许可限制）。遵循 HIG 原则，但不复制 Apple 素材 |

### 启动与 A/B 的两种后端

详细论证见 [ADR 0004](adr/0004-启动与-ota-ab.md)。

- **`uefi-sdboot`**（QEMU 等 UEFI 设备）
  - 启动链：UEFI → systemd-boot → 每个 slot 一个 UKI（由 `ukify` 生成，内含 cmdline）。
  - Alpine 只提供 systemd-boot 的 `.efi`，没有 `bootctl` 和 `systemd-bless-boot`。因此用 mtools 把它拷进 ESP，`loader.conf` 也自己写。
  - 回滚依靠 systemd-boot 的文件名启动计数 `+N-M`。自写 OpenRC 服务 `loong-boot-ok`：从 efivarfs 读取 `LoaderBootCountPath`，去掉文件名中的计数后缀，即标记本次启动成功。这需要加载 `efivarfs` 模块。
- **`android-abl`**（小米平板 5）
  - 设备自带的 ABL 引导从 `boot_a`/`boot_b` 加载 Android `boot.img`（由 `mkbootimg` 生成，附带 dtb）。
  - A/B 切换与回滚使用 `qbootctl`，配合 ABL 自带的重试计数。
  - rootfs 放在 `super` 分区内的 `system_a`/`system_b`，由 initramfs 中的 `loong-dynpart` 映射（功能同 pmOS 的 `make-dynpart-mappings`，但只用 busybox + dmsetup.static）；`/data` 放在 `userdata` 分区。
- 内核 cmdline 统一加 `psi=1`：Alpine 内核默认关闭 PSI，而内存压力回收依赖它。
- 后续增加第三种后端 **`uboot`**，用于 Rockchip、全志、树莓派等，通过 U-Boot bootcount 实现 A/B。

### 多机型支持（从第一天起按此设计）

- **设备层与系统其余部分解耦**：一个机型 = `system/profiles/<机型>.conf` + `loong-device-<机型>` 包。设备包依赖对应的内核和固件，并附带设备描述与音频配置。shell、Web 运行时和系统服务在所有机型上是同一份二进制。
- **设备描述文件 `/usr/share/loong/device.toml`**：记录分辨率、物理尺寸（用于自动计算缩放）、刷新率、默认方向、屏幕圆角半径、安全区、触控旋转矩阵、背光/电池路径、启动后端和分区布局。shell 只根据这个文件适配，不写死任何机型。
- **布局按尺寸类划分**：regular 对应平板，compact 对应手机。v1 只实现平板布局，但设计令牌和组件为手机形态预留了位置。
- **准入条件**：机型需要有主线或接近主线的内核，以及 Mesa 开源 GPU 驱动（高通 Adreno/freedreno、Mali/panfrost/panthor、树莓派 v3d、Intel/AMD）。只有 Android 厂商内核的机型（多数联发科、麒麟等）不在支持范围内：它们需要借助 libhybris 使用 Android 驱动，这与“不基于 Android”的目标冲突。
- **候选机型**：postmarketOS v26.06 已有 222 个 aarch64 设备端口。平板包括小米平板 5/5 Pro/6、Mi Pad 4、联想小新 Pad 2022、小新 Pad Pro 12.6、PineTab2、三星 Galaxy Tab A 等。内核和固件可以直接复用，新增一个机型的主要工作是写设备包和 profile，再上真机调试。
- **架构**：以 aarch64 为主，x86_64 同步构建，因此也能支持 x86 平板。Alpine 还支持 riscv64 和 loongarch64，代码可以在这两个架构上编译；但 loongarch64 上的 WebKit 没有 JIT，性能需要单独评估。
- **新增机型检查清单**：显示/120Hz、触控、GPU、Wi‑Fi、电池、背光、音频、休眠唤醒、OTA 回滚。CI 按 profile 矩阵构建镜像。

### 手机形态（v2，M7）

架构不变：同一套系统镜像根据 `device.toml` 中的尺寸类切换平板或手机布局。手机还需要以下能力，相关软件包在 Alpine/pmOS 中均已确认存在：

- **电话、短信、移动数据**：ModemManager + libqmi/libmbim；callaudiod 负责通话音频路由。电话和短信做成系统 Web 应用，通过 loong-sysd 的受限接口调用 ModemManager。
- **手机 UI**：compact 布局（单列主屏、底部 Dock、刘海/挖孔安全区）、通话界面与全屏来电、锁屏通知。手势沿用同一套物理动画引擎。
- **传感器与反馈**：iio-sensor-proxy 负责自动旋转，以及通话时靠近传感器息屏；feedbackd 负责振动。
- **待机**：休眠时基带保持在线，来电或短信能唤醒设备。电源管理比平板更严格。
- **摄像头**：使用 libcamera。各机型支持程度不一，需逐一评估。
- **参考机型**：一加 6/6T（骁龙 845，主线支持最成熟）；备选 Pixel 3a、Poco F1、Fairphone 4/5、PinePhone Pro。
- **已知限制**：主线内核对 VoLTE 的支持参差不齐，部分机型的通话功能需要在 M7 中逐台验证。

```
┌──────────────── 用户会话 (uid loong) ─────────────────┐
│ loong-shell (Rust/Smithay)                             │
│  ├ 合成器: DRM/KMS+GBM+GLES2, libinput 触控, xdg-shell, │
│  │         text-input-v3 / input-method-v2, loong 私有协议│

│  └ 应用管理: 启动/冻结(cgroup freezer)/内存压力回收(PSI)│

└────────────────────────────────────────────────────────┘
```

### 关键设计

- **单任务全屏模型**（类似 iPad）：v1 不做自由窗口，也不做分屏。
- **启动闪屏由合成器绘制**：使用 manifest 中的 icon 和 background_color。图标放大的弹簧动画正好覆盖 WebKit 的冷启动时间。
- **后台冻结**：应用进入后台 N 秒后，用 cgroup v2 freezer 冻结。PSI 报告内存压力时，按 LRU 顺序结束后台应用，多任务界面改为显示它们的快照。
- **PWA 安装流程**：在浏览器中“添加到主屏幕”→ 解析 W3C manifest → 写入 `~/.local/share/loong/webapps/<id>/` → shell 通过 inotify 发现新应用并播放入场动画。
  - 每个应用有独立的 WebKit 数据目录。
  - 超出 manifest scope 的导航交给浏览器处理。
  - Web Notifications 转发到 shell 实现的 `org.freedesktop.Notifications`。
- **系统应用也是 Web 应用**（设置等）：使用 LoongKit（CSS 设计令牌 + 组件 + JS 弹簧；弹簧曲线可生成 CSS `linear()` 缓动），通过受限的 JS bridge 调用 loong-sysd。
- **浏览器界面（chrome）与网页内容的组合**：WPE 的 Wayland 后端把一个 toplevel 下的所有 view 画到同一个 `wl_surface` 上（没有子表面，max-views 默认为 1），因此无法直接让“界面 + 内容”两个 view 同屏显示。这是 M2 的第一项技术验证。
  - 首选方案：自写 **`loong` WPEPlatform 后端**。每个 view 对应一个 `wl_subsurface`，同时由它承载 loong 私有协议（app_id、theme-color、状态栏样式、启动闪屏交接）。**已实现并验证**（`webrt/platform/`、`webrt/browser/`），见 [ADR 0003 · 实现记录](adr/0003-web-内核-wpe-webkit.md#实现记录m2loong-后端与浏览器)。
  - 备选方案：由 shell 绘制浏览器工具栏，通过私有协议与浏览器通信。
  - 详见 [ADR 0003](adr/0003-web-内核-wpe-webkit.md)。

## 三、物理动画规范（loong-motion）

`crates/loong-motion` 已实现。它是纯数学库，没有第三方依赖，合成器和 Web 端（LoongKit）共用这一套模型。各预设的使用场景见[设计规范 · 动效](design/设计规范.md#7-动效)。

- **弹簧**：使用阻尼谐振子的解析解，覆盖欠阻尼、临界阻尼、过阻尼三种情况。参数为 `response` + `dampingFraction`（与 SwiftUI 含义相同）。动画可以中途打断，打断时继承当前速度（`retarget` / `set_spring` / `jump_to`）。
- **预设**：

  | 预设 | response (s) | dampingFraction |
  |---|---|---|
  | `INTERACTIVE` | 0.15 | 0.86 |
  | `SNAPPY` | 0.3 | 0.85 |
  | `SMOOTH` | 0.5 | 1.0 |
  | `BOUNCY` | 0.5 | 0.7 |
  | `APP_OPEN` | 0.42 | 0.9 |
  | `APP_CLOSE` | 0.38 | 0.82 |

- **惯性衰减**：decelerationRate 分两档，`NORMAL` 为 0.998/ms，`FAST` 为 0.99/ms。`project(v)` 预测最终落点，用于手势决策。
- **橡皮筋**：`f(x) = (1 − 1/(x·c/d + 1))·d`，其中 c = 0.55。另提供反函数，用于在越界区域重新抓取时恢复手指坐标。
- **速度跟踪**：对最近 100ms 的触点做最小二乘拟合。松手前如果停顿超过 40ms，速度视为 0。
- **吸附与分页**：先用投影预测落点，再吸附到最近的合法位置。分页时一次手势最多翻一页。二选一类手势的判定规则是 `progress + project(v) > 0.5`。
- **CSS 缓动**：把弹簧曲线转换为 CSS `linear()` 缓动，供 LoongKit 使用。
- **时间驱动**：由帧时间戳驱动，60Hz 和 120Hz 下结果一致；测试使用虚拟时钟。
- **手势**（iPadOS 式）：
  - 从底边上滑回主屏：窗口跟手缩小，松手后飞回图标。
  - 上滑后停顿：进入多任务。
  - 沿底边横滑：切换应用。
  - 从右上角下滑：打开控制中心。
  - 从左上角下滑：打开通知中心。
  - 主屏分页：投影 + 吸附，首末页边缘有橡皮筋效果。
  - 多任务卡片上滑：关闭应用。

## 五、路线图

| 里程碑 | 内容 | 周期 |
|---|---|---|
| **M0 基础设施** | 文档/ADR、Rust workspace、Alpine chroot、WPE APKBUILD、QEMU 镜像构建器、QEMU 启动测试 | 1–2 周 |
| **M1 Shell 核心** | loong-motion；headless 渲染 → xdg-shell → DRM/KMS + libinput；主屏、Dock、状态栏；打开/关闭动画；回主屏手势；多任务；锁屏 | 4–6 周 |
| **M2 Web 运行时** | 验证 loong WPEPlatform 后端；loong-webapp；loong-browser；PWA 注册表；通知 | 3–4 周 |
| **M3 小米平板 5 适配** | android-abl 启动后端、super 分区 A/B、触控、120Hz、freedreno、Wi‑Fi、电池、背光、音频、休眠 | 3–4 周（与 M2 并行） |
| **M4 系统能力** | 屏幕键盘 + Rime；控制中心；设置 App + loong-sysd；媒体（含硬解）；电源管理 | 4–6 周 |
| **M5 OTA A/B** | dm-verity、两种后端的回滚、loong-update、签名更新包 | 2–3 周 |
| **M6 瘦身与性能** | 自编 mesa（去掉 LLVM）、ICU 裁剪（只保留中英文）、字体子集化、WebKit 内存上限、帧调度、开机速度。rootfs 瘦身（字体子集、中英文 ICU、模块与固件白名单、清理、erofs 簇大小）已完成；连同 mesa-loong，真机配置的只读根 327.7 → 124.8 MiB；WebKit 按体积重编（`-Os` + 热点 `-O2`、关掉用不到的功能）后 101.0 MiB，见[体积预算](体积预算.md) | 持续 |
| **M7 手机形态（v2）** | compact 布局、电话/短信/移动数据、来电唤醒待机、传感器、振动；参考机型一加 6/6T | 6–8 周 |

### v1 资源目标

| 指标 | 目标 |
|---|---|
| 系统镜像（压缩后） | ≤ 250MB；M6 瘦身后 ≤ 150MB（现在真机配置 104 MiB，各部分预算见[体积预算](体积预算.md)） |
| 开机后空闲内存 | ≤ 200MB |
| shell 常驻内存（RSS） | ≤ 40MB |
| nabu 开机时间 | ≤ 6s |
| nabu 帧率 | 120fps |

### 主要风险

| 风险 | 应对 |
|---|---|
| WebKit 编译慢（4 核约 3–6 小时）。GitHub 托管 runner 单个任务最长 6 小时；ARM runner 只对公开仓库免费，私有仓库的 runner 只有 2 核 | 使用 ccache；必要时在开发机或自托管 runner 上构建，再把 APK 发布到 Release |
| Alpine 的 mesa 依赖 LLVM，体积大 | M6 自编 mesa（✅ `mesa-loong`，图形栈 241 MB → 14 MB，见第六节第 9 项） |
| 浏览器要显示多个 view，需要自写 WPEPlatform 后端 | 作为 M2 第一项验证，并准备备选方案（见上文） |
| nabu 部分硬件（摄像头等）支持不完整 | 摄像头不纳入 v1 |
| 合成器工作量大 | 采用单任务全屏模型，分阶段交付 |

9. **M6：自编 Mesa（`system/packages/mesa-loong`）** ✅（x86_64 在 QEMU 中验证；aarch64 包可构建，freedreno 未上真机）
   - 为什么：Alpine 的 `mesa` 把所有驱动编进一个 `libgallium`，并为 llvmpipe/radeonsi 依赖 `llvm22-libs`（182 MiB），再加 SPIRV-Tools、xcb/X11 的 GLX 与 Vulkan 部分，图形栈安装后约 230 MiB，是镜像里最大的一块。
   - 配置（Mesa 26.1.6，与 Alpine 3.24 同版本）：`-Dgallium-drivers=softpipe,virgl`，aarch64 另加 `freedreno`（kmsro 随之自动构建，`-Dfreedreno-kmds=msm`）；`-Dplatforms=wayland`（EGL 另有 GBM 与 surfaceless）；`-Dopengl=false -Dglx=disabled -Dgles1=disabled`，只留 EGL + GLES 2/3；`-Dllvm=disabled`，没有 Vulkan、OpenCL、VA-API；`-Dxmlconfig=disabled`（driconf 默认值编进库里）；保留磁盘着色器缓存（zstd）。`/usr/lib/dri` 下给 X 服务器用的 libdril 桩不打包：Mesa 25 起 EGL 与 GBM 直接链接 libgallium。
   - 子包与 Alpine 对应（`-egl`、`-gles`、`-gbm`），so: 名由 abuild 自动生成，wpewebkit、libepoxy、loong-shell 等不用改。各库子包与发行版 `mesa` 互斥：apk 不会把两套混装，也装不进开发 chroot。
   - `libGL.so.1` 桩（`mesa-loong-glx-stub`）：Alpine 的 gst-plugins-base 带 GLX 平台编译，`libgstgl-1.0` 直接链接 `libGL.so.1`，而 libWPEWebKit 链接 libgstgl；musl 加载时解析全部符号，缺了它 WebKit 起不来。桩只导出 GLX 1.4 的入口、一律报告“没有 GLX”（GStreamer 在 Wayland 上走 EGL，不会调用）。以后 WebKit 不再链接 GStreamer GL，或 gst-plugins-base 改为只编 EGL 时可以去掉。
   - 机型配置用一个变量选图形栈：`MESA_FLAVOR=loong`（默认，三个机型都是）或 `distro`（Alpine 的 mesa，开发时要 llvmpipe 的速度可以 `MESA_FLAVOR=distro system/mkimage/mkimage.sh qemu-x86_64`）。`tools/build-pkg.sh` 新增 `ARCH=aarch64`：在 aarch64 的 Alpine 构建 chroot 里经 qemu-user 打包。
   - 体积（同一棵代码树、`WITH_WPE=1` 的 QEMU x86_64 镜像，只改 `MESA_FLAVOR`）：

     | | Alpine mesa（distro） | mesa-loong |
     |---|---|---|
     | 图形栈安装后（mesa*、llvm22-libs、spirv-tools、libelf、libxshmfence、libxxf86vm） | 241.5 MB | 14.3 MB |
     | 根文件系统（裁剪后，未压缩） | 570 MiB | 354 MiB |
     | 根镜像（erofs，lz4hc） | 327 MiB | **217 MiB** |
     | nabu 软件包集合（模拟安装，未裁剪，不含 WPE） | 680 MiB | 485 MiB |

     aarch64 的 `mesa-loong` 含 freedreno，安装后约 15.1 MiB。libX11/xcb 仍在镜像里：cairo、pango、gst-plugins-base 依赖它们，与 Mesa 无关。
   - 软件渲染的速度（softpipe 没有 JIT，逐像素解释着色器）：无屏幕 `loong-shell` 渲染 `ink-unlock.json`（1280×800，157 帧，原生 x86_64）每帧平均——llvmpipe 21.7 ms，softpipe（-Os）2005 ms，softpipe（-O2）1719 ms；两者画面逐像素对比平均差 < 1/255（圆角、晕染等自定义着色器结果一致）。在 QEMU（TCG）里：锁屏首帧约 45 秒，解锁到主屏约 50 秒（llvmpipe 约 10 秒），设置约 6.5 分钟才显示完整（llvmpipe 约 85 秒），浏览器约 8 分钟；动画只能出几帧。功能验证够用，交互调试请用 `MESA_FLAVOR=distro`。有 GPU 的机型不受影响；QEMU 若宿主机有 GPU，可以用 virgl（`-device virtio-gpu-gl`，镜像里已有 virgl 驱动，开发沙箱没有 DRM 设备，未验证）。
   - -Os 还是 -O2：-O2 的 libgallium 大 21%（16.7 vs 13.7 MB），softpipe 只快约 15%，选 -Os；freedreno 的 CPU 开销上真机后再量。
   - 待做：nabu 上机验证 freedreno（自定义着色器、WebKit 的 dmabuf 零拷贝）；考虑 `-Db_lto=true`（Alpine 因上游问题关闭，约小 5%）；WebKit 若去掉 GStreamer GL，可删掉 libGL 桩。

10. **音视频：最小 GStreamer 插件集（`system/packages/gst-plugins-loong`）** ✅（QEMU 中验证；nabu 的硬解与扬声器未上真机）
   - 问题：镜像里只有 gst-plugins-base（wpewebkit 依赖它的库），WebKit 建音频输出要 gst-plugins-good 的 `autoaudiosink`，拿不到就 `RELEASE_ASSERT`，任何 `<video>`/`<audio>` 都让网页进程崩溃。Alpine 的 gst-plugins-good 是一个全家桶包（连带 X11、PulseAudio、libraw1394、cairo、gdk-pixbuf、lame 等），不装。
   - 做法：从源码编 gst-plugins-good 1.28.3（与 Alpine 的 gstreamer 同版本）的子集，`--auto-features=disabled`，只开 autodetect、interleave（Web Audio 的 deinterleave）、audiofx（scaletempo）、isomp4、matroska、audioparsers、wavparse、id3demux/apetag、icydemux、vpx、mpg123、v4l2（不用 libv4l2、libgudev）；再从 gst-plugins-bad 只编 videoparsers（h264parse 等，V4L2 硬解与 MSE 要）和 opusparse（MSE 的 Opus 要），连带 libgstcodecparsers，其余 -bad 库不编译。插件装在标准目录，与 Alpine 的 gst-plugins-good/bad 互斥（`depends` 在 `package()` 里赋值，免得 abuild 把互斥当成构建依赖去卸载开发 chroot 里的发行版插件）。
   - 格式：软件解码 WebM（VP8/VP9 + Opus/Vorbis）、Ogg（Theora/Vorbis/Opus）、MP3、WAV，MSE 支持 WebM；MP4 能解封装，H.264/HEVC/VP9 在 nabu 上走 Venus（V4L2 有状态解码器，DMA-BUF 经 GStreamer GL 零拷贝）；AAC 与 H.264 软解见下一项。详见[媒体格式](媒体格式.md)。
   - 体积：gst-plugins-loong 2.7 MiB + libvpx 3.2 MiB + libmpg123 0.4 MiB，真机配置的只读根 101.0 → 104.0 MiB（+3.0 MiB）。
   - 构建：x86_64 不到 1 分钟；aarch64（`ARCH=aarch64 JOBS=2 tools/build-pkg.sh gst-plugins-loong`，经 qemu-user）约 9 分钟，安装后 3.0 MB（64 KiB 页对齐，小插件各占 64 KiB），在 Alpine aarch64 上依赖可解析；还没在 aarch64 镜像里跑过（本地还没有 aarch64 的 wpewebkit 包）。
   - 音频输出：没有声卡时 `autoaudiosink` 退回 `fakesink`，照常播放（QEMU）；nabu 的扬声器见下一项。
   - 待做：nabu 上确认 venus 驱动与注册的解码器、DMA-BUF 零拷贝；libvpx 只编解码器（Alpine 的带编码器）。
11. **MP4 软解（`system/packages/ffmpeg-loong`）与 nabu 扬声器** ✅（QEMU 中验证；nabu 未上真机）
   - 问题：网站最常见的 MP4（H.264 + AAC，MSE 里是 fMP4）在没有硬解的机器上放不了，nabu 上 AAC 也没有解码器；nabu 的扬声器没人启用 UCM 用例，没有声音。
   - 做法：FFmpeg 8.1.3（与 Alpine 同版本）`--disable-everything`，只开 `h264`、`aac` 解码器，LGPL、汇编开着、`--enable-small`、LTO，不要 libavformat/libavfilter/libswscale/libswresample；同一个 APKBUILD 编 gst-libav 1.28.3（子包 `gst-libav-loong`，补丁只编 `avdec_*`）。库在私有目录 `/usr/lib/ffmpeg-loong`（`sonameprefix`，插件带 RUNPATH），不与 Alpine 的 ffmpeg-libs 冲突。HEVC 不编软解（+0.78 MiB；nabu 走 Venus）。专利与发行方式见[媒体格式](媒体格式.md#专利与许可证)：公开发行前要决定是取得许可还是把它做成用户自装的附加包。
   - 结果：QEMU 中 MP4、MSE fMP4、M4A、AAC 的 `decodeAudioData` 都播放到结尾；`canPlayType` 对 `avc1.*`、`mp4a.40.2/5` 报告 probably，MSE 支持；真机配置的只读根 104.0 → 104.9 MiB（+0.86 MiB）。
   - nabu 扬声器：机型目录里的 `loong-audio`（OpenRC 服务 + udev 规则）在开机与声卡出现时用 `alsaucm` 设 `HiFi` / `Speaker`；`/usr/share/alsa/cards/sm8150.conf` 让 ALSA 默认设备经 dmix，多个网页进程同时出声（WPE 的沙箱不隔离 IPC）。`alsa-utils` 连同依赖使 nabu 只读根 +2.3 MiB，以后由 loong-sysd 经 alsa-lib 设用例后去掉。上机检查步骤见 [nabu 适配说明](devices/xiaomi-nabu.md#音频扬声器)。
